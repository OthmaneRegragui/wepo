# Compatibility

Last updated: 2026-11-02

Wepo Office targets a tested subset of the Office Open XML formats. This page
records what has actually been checked and where the editors stop. It is not a
claim of Microsoft Office compatibility.

## Format policy

| Format | Open | Edit | Save/export | Notes |
|---|---|---|---|---|
| DOCX | Yes | Yes | DOCX, print/PDF | OOXML word-processing |
| XLSX | Yes | Yes | XLSX, CSV, print/PDF | OOXML workbook |
| CSV | Yes | Yes | XLSX, CSV | Converted to XLSX locally before editing |
| PPTX | Yes | Yes | PPTX, print/PDF | OOXML presentation |
| DOC / XLS / PPT | No | No | No | Re-save as the OOXML equivalent |
| ODT / ODS / ODP | No | No | No | Re-save as the OOXML equivalent |
| RTF / TXT | No | No | No | Re-save as DOCX |
| PDF | No | No | Print target only | PDF is a print output, not an editable input |

Unsupported files are rejected before any engine starts. The error message
names the required re-save format.

## Verified environment

- Browsers: Chromium 1248 (Playwright bundled build), headless.
- OS: Linux.
- Production preview: Vite preview on `http://localhost:4173`.
- Cross-origin isolation: `crossOriginIsolated === true`; `SharedArrayBuffer`

## Known limitations

- The suite is a browser editor, not Microsoft Office. Complex layout may shift.
- Fonts are metric-compatible substitutes, not the proprietary Office fonts.
  CJK families are not bundled; they depend on the browser and OS.
- Password-protected Office files are rejected.
- ZIP64 containers are rejected.
- CSV is a single-table interchange format. Formatting, formulas, multiple
  sheets, and images are not part of CSV export.
- The Slides print/PDF path omits pictures. Export PPTX to keep them.
- The Sheets print path clips very large worksheets at the engine's cell budget.
- Recovery copies are stored in IndexedDB and are limited to 50 MB per
  document, 25 documents, and 300 MB total.
- Cross-origin isolation is required for the worker path. A host that cannot
  send COOP/COEP headers may not run the Sheets editor correctly.

## How to test a file

1. Run `npm run build && npm run preview`.
2. Open the relevant app page.
3. Use the file picker or drop zone. The original file is not modified.
4. Confirm the editor reports ready and shows the expected content.
5. Make a small edit, use **Save a copy**, and inspect the new file.
6. Reopen the exported file in the original application.
7. Record the result in the table above, including the producer and version.

If a file fails, note the producer, version, file size, and the on-screen error.
Do not include confidential document contents in a public issue.
